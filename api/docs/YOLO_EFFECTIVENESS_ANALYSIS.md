# YOLO 모델 사용 효과 분석

## 현재 YOLO 사용 방식

### 1. 하이브리드 접근 (보조적 사용)
- **주**: OCR/파싱 기반 강의 감지
- **보조**: YOLO로 감지된 강의 중 OCR/파싱에서 누락된 것만 추가

### 2. 병합 로직
```python
# YOLO로만 감지된 강의 추가 (OCR/파싱에서 누락된 경우)
for yolo_lec in yolo_lectures_for_merge:
    yolo_page = yolo_lec.get('page', 0)
    # 같은 페이지에 OCR/파싱 강의가 없으면 YOLO 강의 추가
    if yolo_page not in ocr_pages:
        lectures.append(yolo_lec)
```

## 실제 성능 데이터

### 이전 테스트 결과 (50페이지)
- **YOLO 감지**: 13개 강의
- **OCR/파싱 감지**: 80개 강의
- **병합 후**: 93개 강의 (YOLO가 13개 추가)
- **최종 유효**: 89개 강의

### YOLO의 실제 기여도
1. **Header 감지 정확도**: 낮음 (4개/73개 예상 → 실제로는 더 적음)
2. **추가 강의**: 13개 추가했지만, 실제로 유효한지 불확실
3. **처리 시간**: 매우 느림 (API 호출이 순차적)

## 문제점

### 1. 성능 문제
- **YOLO API 호출**: 순차적 처리로 매우 느림
- **이미지 변환**: PDF → 이미지 변환 시간 추가
- **샘플링 적용**: 50페이지만 처리해도 시간이 오래 걸림

### 2. 정확도 문제
- **Header 감지**: 정확도가 낮아서 대부분의 강의를 놓침
- **중복 감지**: OCR/파싱과 중복되는 경우가 많음
- **False Positive**: 잘못 감지된 강의가 포함될 수 있음

### 3. 비용 문제
- **Roboflow API**: 호출 비용 발생
- **처리 시간**: 사용자 대기 시간 증가

## 결론

### YOLO를 사용해야 하는 경우
1. ✅ **레이아웃이 복잡한 PDF**: OCR/파싱이 실패하는 경우
2. ✅ **스캔된 PDF**: 텍스트 레이어가 없는 경우
3. ✅ **정확한 bbox가 필요한 경우**: 이미지 크롭에 정확한 좌표 필요

### YOLO를 사용하지 않아도 되는 경우
1. ✅ **텍스트 레이어가 있는 PDF**: pdfplumber로 충분히 처리 가능
2. ✅ **빠른 처리가 필요한 경우**: YOLO는 느림
3. ✅ **OCR/파싱이 잘 작동하는 경우**: 대부분의 강의를 잘 감지함

## 권장 사항

### 현재 상황 (수능특강 문학)
- **PDF 특성**: 텍스트 레이어 있음 (pdfplumber 사용 가능)
- **OCR/파싱 성능**: 80개 강의 감지 (충분히 좋음)
- **YOLO 기여도**: 낮음 (13개 추가, 정확도 불확실)

### 추천: **YOLO 비활성화**
1. **성능**: 훨씬 빠름 (API 호출 없음)
2. **정확도**: OCR/파싱이 대부분의 강의를 잘 감지
3. **비용**: API 호출 비용 없음

### YOLO를 사용해야 하는 경우
- OCR/파싱이 실패하는 특정 페이지가 있을 때
- 레이아웃이 매우 복잡한 경우
- 정확한 bbox가 필수인 경우

## 대안

### 1. 선택적 YOLO 사용
- 특정 페이지 범위만 YOLO 사용
- OCR/파싱 실패 시에만 YOLO 사용

### 2. 로컬 YOLO 모델
- API 대신 로컬 모델 사용 (더 빠름)
- 하지만 모델 로딩 시간과 메모리 사용량 증가

### 3. YOLO 결과 캐싱
- 한 번 감지한 결과를 캐시하여 재사용
- 하지만 PDF가 변경되면 무효화
