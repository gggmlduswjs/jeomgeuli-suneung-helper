# YOLO 성능 분석

## 현재 구조

### YOLO 처리 방식
```
456개 페이지
  ↓
페이지별 순차 처리 (Roboflow API 호출)
  ↓
각 페이지당 약 1-2초 소요
  ↓
총 예상 시간: 456 × 1.5초 = 약 684초 (11분 이상)
```

### OCR/파싱 처리 방식
```
456개 페이지
  ↓
병렬 처리 (여러 워커 동시 실행)
  ↓
각 페이지당 약 0.1-0.3초 (pdfplumber 사용 시)
  ↓
총 예상 시간: 456 × 0.2초 / 워커 수 = 약 30-60초
```

## 성능 비교

| 방식 | 처리 시간 (456페이지) | 장점 | 단점 |
|------|---------------------|------|------|
| **YOLO (현재)** | **11분 이상** | 레이아웃 감지 정확 | 매우 느림, API 호출 비용 |
| **OCR/파싱** | **30-60초** | 빠름, 병렬 처리 | 정확도가 낮을 수 있음 |
| **YOLO + OCR 결합** | **11분 + 30초** | 정확도 높음 | 매우 느림 |

## 문제점

1. **YOLO는 순차 처리**: 페이지별로 API 호출이 필요하여 병렬화 불가
2. **전체 페이지 처리**: 456페이지 모두 처리하면 너무 오래 걸림
3. **Header 감지 부족**: 4개만 감지 (실제 73개)

## 개선 방안

### 1. YOLO 선택적 사용 (권장)

특정 페이지만 YOLO로 처리:
- 샘플링: 10페이지마다 1페이지만 YOLO 처리
- 특정 범위만: 예) 8-100페이지만 YOLO 처리

### 2. YOLO 비활성화

OCR/파싱만 사용:
- 빠른 처리 (30-60초)
- 정확도는 낮을 수 있음

### 3. YOLO 병렬 처리 (제한적)

여러 페이지를 동시에 처리:
- Roboflow API 제한 고려
- 동시 요청 수 제한 필요

## 권장 설정

### 빠른 처리 (기본)
```python
use_yolo = False  # YOLO 비활성화
# OCR/파싱만 사용: 30-60초
```

### 정확도 우선 (선택적)
```python
use_yolo = True
max_yolo_pages = 50  # 처음 50페이지만 YOLO 처리
# YOLO: 50 × 1.5초 = 75초
# OCR: 456 × 0.2초 / 워커 = 30초
# 총: 약 105초 (1분 45초)
```

### 균형잡힌 방식
```python
use_yolo = True
yolo_sample_rate = 0.1  # 10% 페이지만 YOLO 처리
# YOLO: 46 × 1.5초 = 69초
# OCR: 456 × 0.2초 / 워커 = 30초
# 총: 약 99초 (1분 39초)
```
