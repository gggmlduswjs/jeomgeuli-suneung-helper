# AI/ML 기능 역할 분리 (관리자 vs 사용자)

## 🎯 핵심 질문: 관리자가 인프라 제공하면 AI/ML이 필요 없나?

**답: 필요함! 하지만 역할이 분리됨**

---

## 📊 역할 분리 매핑

### 👨‍💼 관리자용 (백엔드/인프라)

**목적**: EBS PDF → 커리큘럼 생성 → DB 저장

#### ✅ 필요한 AI/ML 기능

| 기능 | 기술 스택 | 구현 위치 | 이유 |
|------|----------|----------|------|
| **PDF 구조 분석** | CNN (PyTorch) | `api/app/services/pdf_extract/` | 문제 영역, 지문 블록 감지 |
| **강의대본 → 레슨 블록 분해** | LLM (OpenAI/Gemini) | `api/app/services/curriculum_generator.py` | HWP 분석해서 학습 단위로 분해 |
| **레슨 블록 생성 파이프라인** | LangChain | `api/app/services/curriculum_template.py` | 단계별 처리, 검증, 재시도 |
| **텍스트 정제/전처리** | Hugging Face 모델 | `api/app/services/lecture_script_parser.py` | 한국어 문단 분할, 요약 |

**작업 흐름**:
```
EBS PDF 수신
  ↓
[CNN] PDF 구조 분석 (문제/지문 영역 감지)
  ↓
[HWP 분석] 강의대본 추출
  ↓
[LangChain] 파이프라인 시작
  ↓
[LLM] 강의대본 → 레슨 블록 JSON 생성
  ↓
[검증] JSON 스키마 확인
  ↓
[DB 저장] 커리큘럼 완성
  ↓
사용자에게 즉시 제공
```

---

### 👤 사용자용 (프론트엔드)

**목적**: 이미 준비된 커리큘럼 조회 → 학습 → 점자/음성 출력

#### ✅ 필요한 AI/ML 기능

| 기능 | 기술 스택 | 구현 위치 | 이유 |
|------|----------|----------|------|
| **점자 출력** | 규칙 기반 매핑 | `apps/web/src/hooks/braille/` | 레슨 블록 → 점자 3셀 신호 |
| **음성 알림** | TTS (Web Speech API) | `apps/web/src/hooks/useTTS.ts` | 레슨 전환 시 알림 |
| **학습 흐름 제어** | 상태 관리 | `apps/web/src/store/` | 다음 블록 자동 진행 |

**작업 흐름**:
```
커리큘럼 선택
  ↓
레슨 클릭
  ↓
[점자 출력] 레슨 블록 → 점자 디바이스
  ↓
[음성 알림] "다음 섹션으로 넘어갑니다"
  ↓
학습 진행
```

## 🔥 핵심 포인트

### 1. AI/ML은 여전히 필요함

**이유**:
- 관리자가 **자동으로** 커리큘럼 생성하려면 AI 필요
- 수동으로 하면 시간이 너무 오래 걸림
- EBS PDF 발행 즉시 → 자동 분석 → 즉시 제공

### 2. 역할 분리로 더 명확해짐

**관리자**:
- AI/ML로 **콘텐츠 생성** (LLM, LangChain, CNN)
- 복잡한 분석 로직은 백엔드에서 처리

**사용자**:
- AI/ML로 **학습 경험 향상** (점자 출력, 음성 알림)
- 단순하고 빠른 조회/학습

### 3. 졸업작품으로서의 가치

**증명할 수 있는 것**:
1. ✅ **생성형 AI 활용**: LLM으로 학습 구조 자동 생성
2. ✅ **딥러닝 활용**: CNN으로 PDF 구조 분석
3. ✅ **AI 파이프라인**: LangChain으로 복잡한 워크플로우 설계
4. ✅ **접근성 AI**: AI 결과를 점자/음성으로 실시간 전달
5. ✅ **실제 동작**: 관리자-사용자 분리된 실제 시스템

## 📋 구현 우선순위 (MVP 기준)

### ✅ 반드시 구현 (관리자용)

1. **LLM 기반 레슨 블록 생성**
   - 위치: `api/app/services/curriculum_generator.py`
   - 기술: OpenAI API / Gemini API
   - 입력: HWP 텍스트
   - 출력: 레슨 블록 JSON

2. **LangChain 파이프라인**
   - 위치: `api/app/services/curriculum_template.py`
   - 기술: LangChain
   - 역할: 단계별 처리, 검증, 재시도

3. **PDF 구조 분석 (1강만)**
   - 위치: `api/app/services/pdf_extract/`
   - 기술: CNN (PyTorch) - 간단한 버전
   - 역할: 문제 영역 감지

### ✅ 반드시 구현 (사용자용)

1. **점자 출력**
   - 위치: `apps/web/src/hooks/braille/`
   - 기술: 규칙 기반 매핑
   - 역할: 레슨 블록 → 점자 3셀 신호

2. **음성 알림**
   - 위치: `apps/web/src/hooks/useTTS.ts`
   - 기술: Web Speech API
   - 역할: 레슨 전환 시 알림

### ⚠️ 선택적 (나중에)

- RNN (필요 없음)
- 고급 ML 분석 (오답 패턴 등)
- 복잡한 CNN 모델 (간단한 버전으로 충분)

## 🎓 졸업작품 발표용 한 줄 요약

> **"생성형 AI(LLM)와 딥러닝(CNN)을 활용해 학습 콘텐츠를 자동 생성하고, 
> 그 결과를 점자와 음성으로 실시간 전달하는 접근성 AI 학습 시스템"**

**기술 스택**:
- 생성형 AI: LLM (OpenAI/Gemini) + LangChain
- 딥러닝: CNN (PyTorch)
- 접근성: 점자 출력 + 음성 알림
- 역할 분리: 관리자(생성) + 사용자(학습)

## 💡 결론

**질문**: 관리자가 인프라 제공하면 AI/ML이 필요 없나?

**답**: 
- ❌ 필요 없어지는 게 아님
- ✅ 역할이 분리됨
- ✅ 관리자 = AI로 콘텐츠 생성
- ✅ 사용자 = AI 결과를 점자/음성으로 전달
- ✅ **둘 다 AI/ML 필요함, 용도만 다름**

**졸업작품 가치**:
- AI/ML 없이는 수동 작업만 가능 (시간 오래 걸림)
- AI/ML 있으면 자동화 가능 (EBS 발행 즉시 제공)
- **"AI로 실제 문제 해결" 증명 가능**
