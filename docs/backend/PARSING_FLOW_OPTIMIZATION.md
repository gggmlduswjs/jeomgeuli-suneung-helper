# 파싱 플로우 최적화 제안

## 🔍 현재 플로우 (비효율적)

```
1. 전체 PDF OCR 추출 (456페이지 모두)
   ↓ (느림, 9시간 걸림)
2. 템플릿 매칭 (첫 3-5페이지만 사용)
   ↓
3. 파싱
```

**문제:**
- 템플릿 매칭에 첫 3-5페이지만 필요한데 전체를 추출함
- 456페이지 전체 OCR에 9시간 소요
- 템플릿 매칭 실패해도 이미 전체 추출 완료

---

## ✅ 최적화된 플로우 (제안)

```
1. 첫 3-5페이지만 OCR 추출 (빠름, 10-30초)
   ↓
2. 템플릿 매칭
   ↓
   [템플릿 매칭 성공?]
   ├─ YES (신뢰도 85% 이상)
   │   → 전체 OCR 추출 (템플릿 사용)
   │   → 파싱 (2-5초)
   │
   └─ NO
       → 전체 OCR 추출
       → AI 파싱 시도 (60-120초)
       → 실패 시 config.json 폴백
```

**장점:**
- 템플릿 매칭 실패 시에만 전체 추출
- 템플릿 매칭 성공 시 빠른 경로 (5초)
- 불필요한 전체 OCR 방지

---

## 📊 성능 비교

### 현재 (전체 OCR 먼저)
- 템플릿 매칭 성공: 9시간 (전체 OCR) + 5초 (파싱) = **9시간**
- 템플릿 매칭 실패: 9시간 (전체 OCR) + 60초 (AI) = **9시간**

### 최적화 후 (샘플 먼저)
- 템플릿 매칭 성공: 30초 (샘플) + 9시간 (전체 OCR) + 5초 (파싱) = **9시간**
- 템플릿 매칭 실패: 30초 (샘플) + 9시간 (전체 OCR) + 60초 (AI) = **9시간**

**아, 여전히 전체 OCR이 필요하네요...**

---

## 🤔 진짜 문제

**템플릿 매칭이 실패해도 전체 OCR은 필요합니다.**
- 템플릿 매칭: 첫 3-5페이지만으로 패턴 확인
- 실제 파싱: 전체 페이지 필요

**그럼 최적화 포인트는?**
1. **템플릿 매칭 실패 시:** 전체 OCR 후 AI 파싱
2. **템플릿 매칭 성공 시:** 전체 OCR 후 템플릿 파싱

**둘 다 전체 OCR이 필요하므로...**

---

## 💡 실제 최적화 방안

### 1. OCR 병렬 처리 최적화 ✅ (이미 적용)
- `max_workers = cpu_count() - 1`
- 진행률 실시간 업데이트 ✅

### 2. 템플릿 매칭 캐싱 ✅ (이미 적용)
- 같은 교재는 캐시 사용
- 두 번째 파싱 시 즉시 템플릿 사용

### 3. 부분 OCR 최적화 (새로 제안)
- 첫 3-5페이지만 먼저 추출
- 템플릿 매칭
- 매칭 성공 시에만 전체 추출
- 매칭 실패 시에도 전체 추출 (AI 파싱 필요)

**결론: 여전히 전체 OCR이 필요하지만, 템플릿 매칭 실패를 빨리 알 수 있음**

---

## 🎯 최종 답변

**현재 플로우:**
1. ✅ 전체 PDF OCR 추출 (전체 페이지)
2. ✅ 템플릿 매칭 (첫 3-5페이지만 사용)
3. ✅ 파싱

**템플릿 매칭은 텍스트 추출 후에 일어납니다.**
- 전체 OCR 추출이 먼저
- 그 다음 템플릿 매칭 (첫 3-5페이지만 사용)

**최적화 여지:**
- 첫 3-5페이지만 먼저 추출해서 템플릿 매칭
- 매칭 실패를 빨리 알 수 있음
- 하지만 여전히 전체 OCR은 필요 (파싱에 필요)
