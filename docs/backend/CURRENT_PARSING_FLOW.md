# 현재 파싱 플로우 분석

## 🔍 현재 순서

```
1. 전체 PDF OCR 추출 (전체 페이지, 456페이지면 9시간)
   ↓
2. HybridRouter.select_parser() 호출
   ↓
3. _try_template_matching() 실행
   - ocr_data의 첫 3-5페이지만 사용
   - 템플릿 매칭 시도
   ↓
4. 템플릿 매칭 성공?
   ├─ YES → 템플릿 기반 파서 사용
   ├─ NO → AI 파싱 시도
   └─ 실패 → config.json 폴백
   ↓
5. 파싱 실행 (전체 ocr_data 사용)
```

## ⚠️ 문제점

**비효율적:**
- 템플릿 매칭에 첫 3-5페이지만 필요한데 **전체 456페이지를 먼저 추출**
- 템플릿 매칭 실패해도 이미 전체 추출 완료
- 9시간 소요 후 템플릿 매칭 실패하면 AI 파싱 (추가 60초)

## ✅ 최적화 제안

### 옵션 1: 샘플 먼저 추출 (추천)

```
1. 첫 3-5페이지만 OCR 추출 (30초)
   ↓
2. 템플릿 매칭
   ↓
   [매칭 성공?]
   ├─ YES → 전체 OCR 추출 (9시간) → 템플릿 파싱 (5초)
   └─ NO → 전체 OCR 추출 (9시간) → AI 파싱 (60초)
```

**장점:**
- 템플릿 매칭 실패를 30초 만에 알 수 있음
- 여전히 전체 OCR은 필요하지만, 실패를 빨리 알 수 있음

**단점:**
- 두 번 OCR 추출 (샘플 + 전체)
- 하지만 샘플은 30초면 충분

### 옵션 2: 현재 유지 + 진행률 개선 (현재 적용)

```
1. 전체 OCR 추출 (9시간, 진행률 실시간 업데이트)
   ↓
2. 템플릿 매칭 (첫 3-5페이지만 사용)
   ↓
3. 파싱
```

**장점:**
- 한 번만 OCR 추출
- 진행률 실시간 업데이트로 사용자가 진행 상황 확인 가능

**단점:**
- 템플릿 매칭 실패를 9시간 후에야 알 수 있음

---

## 💡 결론

**현재:**
- ✅ 텍스트 추출이 먼저 (전체 페이지)
- ✅ 템플릿 매칭이 그 다음 (첫 3-5페이지만 사용)

**최적화 여지:**
- 첫 3-5페이지만 먼저 추출해서 템플릿 매칭
- 매칭 실패를 빨리 알 수 있음
- 하지만 여전히 전체 OCR은 필요 (파싱에 필요)

**실제로는:**
- 템플릿 매칭 실패해도 전체 OCR은 필요
- 따라서 큰 차이는 없지만, 실패를 빨리 알 수 있음

---

## 🎯 권장 사항

**현재 상태 유지 + 진행률 개선 (이미 적용됨)**
- OCR 진행률 실시간 업데이트 ✅
- 사용자가 진행 상황 확인 가능 ✅

**추가 최적화 (선택):**
- 첫 3-5페이지만 먼저 추출
- 템플릿 매칭
- 매칭 실패 시 경고 표시
- 하지만 여전히 전체 OCR 진행
