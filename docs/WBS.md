### 일반적인 소프트웨어 개발 순서

일반적으로 소프트웨어 개발은 다음과 같은 순서를 따릅니다:

1. **MVP (Minimum Viable Product)** - 핵심 기능 먼저
   - 사용자가 실제로 사용할 수 있는 최소 기능
   - 빠른 피드백 수집
   - 시장 검증

2. **인프라 구축** - 확장 가능한 기반
   - 데이터베이스 설계
   - API 구조
   - 모니터링/로깅

3. **기능 확장** - 사용자 피드백 기반
   - 사용자 요청 기능
   - 사용 패턴 분석 기반 개선

4. **고급 기능** - 차별화
   - AI/ML 기능
   - 자동화
   - 최적화

### 현재 순서의 특징

**현재 프로젝트의 개발 순서는 "제작자 확대 전략" 중심입니다:**

#### ✅ 장점

1. **제작자 생산성 우선**
   - 제작 시간 단축 → 더 많은 콘텐츠 제공 가능
   - 자동화로 제작자 확대 용이
   - 사용자 확대의 전제 조건

2. **데이터 인프라 우선**
   - AI/ML 기능을 위한 데이터 수집 인프라 먼저 구축
   - 데이터가 쌓여야 추천 시스템이 효과적

3. **점진적 복잡도 증가**
   - 단순한 규칙 기반 → ML 모델 → 생성형 AI
   - 기술적 리스크 관리

#### ⚠️ 단점 및 고려사항

1. **사용자 체감 기능이 늦음**
   - 학습자 입장에서는 2차개발부터 체감 가능
   - 초기 사용자 만족도가 낮을 수 있음

2. **병렬 개발 가능성**
   - 일부 기능은 병렬 개발 가능
   - 예: 커리큘럼 자동화와 PDF UI는 독립적

3. **의존성 관리**
   - 추천 시스템은 사용자 데이터가 필요
   - 하지만 기본 추천은 규칙 기반으로 먼저 가능

### 워킹 스켈레톤 (Working Skeleton) 방식

**워킹 스켈레톤이란?**
- 전체 시스템의 기본 골격을 먼저 구축
- 엔드투엔드 흐름을 완성한 후 기능 추가
- "동작하는 최소한의 전체 시스템" 먼저 만들기

#### 워킹 스켈레톤 방식 적용 예시

```
Phase 0: 워킹 스켈레톤 (4주)
  - 홈 화면
  - 교재 선택 → 학습 화면 → 문제 풀기 (기본 흐름)
  - 점자 디바이스 연동 (기본)
  - PDF 읽기 (기본)
  - 문제 풀이 (기본)
  → 사용자가 실제로 학습할 수 있는 최소 기능

Phase 1: 제작자 기능 추가 (3주)
  - 제작 자동화
  - 커리큘럼 생성
  → 더 많은 콘텐츠 제공

Phase 2: 사용자 경험 개선 (8주)
  - ML 동기화
  - 추천 시스템
  → 학습 효율성 향상

Phase 3: 고급 기능 (12주)
  - 생성형 AI
  - ML 모델
  → 차별화
```

#### 워킹 스켈레톤 방식의 장점

1. **조기 사용자 피드백**
   - 전체 흐름을 빠르게 검증 가능
   - 사용자 반응 조기 확인

2. **통합 테스트 용이**
   - 엔드투엔드 흐름이 일찍 완성
   - 통합 이슈 조기 발견

3. **동기 부여**
   - 실제 동작하는 시스템을 빠르게 확인
   - 개발팀 사기 향상

4. **유연한 우선순위 조정**
   - 사용자 피드백에 따라 우선순위 변경 용이

#### 워킹 스켈레톤 방식의 단점

1. **초기 품질이 낮을 수 있음**
   - 빠른 구현으로 인한 기술 부채
   - 리팩토링 필요

2. **제작자 확대 지연**
   - 제작 자동화가 늦어짐
   - 콘텐츠 확대 속도 저하

#### 현재 프로젝트에 워킹 스켈레톤 적용 시
