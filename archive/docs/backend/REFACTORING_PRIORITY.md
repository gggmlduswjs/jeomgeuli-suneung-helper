# PDF 파싱 리팩토링 우선순위

## 현재 문제점

### 1. 에러 처리 부족 (긴급)
- **문제**: None 체크와 타입 검증이 일관되지 않음
- **영향**: 런타임 에러 발생 (TypeError: cannot unpack, NoneType 비교 등)
- **파일**: 
  - `section_extractor.py` (튜플 언패킹 에러)
  - `lecture_contents_extractor.py` (None 비교 에러)
  - `unified_parser.py` (템플릿 없음 경고 반복)

### 2. 파싱 속도 문제 (중요)
- **문제**: 전체 페이지(456페이지)를 모두 추출
- **영향**: 불필요한 처리로 인한 속도 저하
- **해결**: 템플릿의 강의 목록을 활용하여 필요한 페이지만 추출

### 3. 템플릿 활용 미흡 (중요)
- **문제**: 템플릿이 있어도 매칭 실패 시 폴백 사용
- **영향**: 영역 정보(region_hints, region_text_examples) 미활용
- **해결**: 템플릿 강제 사용 로직 추가 (완료)

### 4. 코드 중복 (중간)
- **문제**: 여러 파서에서 유사한 로직 반복
- **영향**: 유지보수 어려움
- **해결**: UnifiedParser로 통합 (진행 중)

### 5. 로깅 일관성 부족 (중간)
- **문제**: 로그 형식이 일관되지 않음
- **영향**: 디버깅 어려움
- **해결**: 구조화된 로깅 도입

## 리팩토링 계획

### Phase 1: 긴급 수정 (즉시)
1. ✅ None 체크 및 타입 검증 강화
2. ✅ 템플릿 강제 사용 로직 추가
3. ✅ 템플릿 기반 페이지 범위 최적화
4. ⏳ 에러 처리 표준화

### Phase 2: 성능 최적화 (우선)
1. ✅ 템플릿 기반 페이지 범위 계산
2. ✅ 필요한 페이지만 추출
3. ⏳ 병렬 처리 최적화

### Phase 3: 코드 품질 개선 (중기)
1. 코드 중복 제거
2. 타입 힌트 강화
3. 문서화 개선

### Phase 4: 아키텍처 개선 (장기)
1. 의존성 주입 개선
2. 테스트 코드 추가
3. 모니터링 강화

## 즉시 수정 필요 항목

1. **에러 처리 강화**
   - 모든 None 체크 추가
   - 타입 검증 강화
   - 안전한 언패킹

2. **템플릿 기반 최적화**
   - 템플릿의 강의 목록으로 페이지 범위 계산
   - 필요한 페이지만 추출
   - 불필요한 처리 제거

3. **로깅 개선**
   - 템플릿 사용 여부 명확히 표시
   - 성능 메트릭 추가
   - 에러 컨텍스트 강화
