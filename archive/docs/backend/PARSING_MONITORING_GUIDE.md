# 파싱 진행 상황 모니터링 가이드

## 문제점

파싱이 진행 중인지 확인하기 어려움:
- 로그 파일이 별도로 저장되지 않음
- 백그라운드 작업이라 콘솔 출력을 보기 어려움
- 실시간 진행 상황을 알 수 없음

## 해결 방법

### 방법 1: 파싱 상태 확인 스크립트 (가장 간단)

```bash
cd backend
python scripts/check_parsing_status.py
```

**특정 교재 확인:**
```bash
python scripts/check_parsing_status.py {book_id}
```

**출력 예시:**
```
============================================================
파싱 상태 확인
============================================================
확인 시간: 2026-01-23 20:30:00

⏳ 수능특강 문학
  ID: book_korean_2026_수능특강_문학_d139df
  상태: PROCESSING
  진행률: 45%
  페이지: 45/100
  강의 수: 0개
  생성 시간: 2026-01-23 20:25:00
```

### 방법 2: 실시간 모니터링 (자동 업데이트)

```bash
cd backend
python scripts/monitor_parsing.py {book_id}
```

**모든 파싱 중인 교재 모니터링:**
```bash
python scripts/monitor_parsing.py
```

**출력 예시:**
```
============================================================
파싱 진행 상황 모니터링
============================================================
확인 간격: 5초

[20:30:00] ⏳ 수능특강 문학
  상태: PROCESSING
  진행률: 45%
  페이지: 45/100

[20:30:05] ⏳ 수능특강 문학
  상태: PROCESSING
  진행률: 50%
  페이지: 50/100

[20:30:10] ✅ 수능특강 문학
  상태: DONE
  진행률: 100%
  페이지: 100/100

파싱이 완료되었습니다!
```

### 방법 3: 관리자 페이지에서 확인

1. 관리자 페이지 접속: `http://localhost:3000/admin`
2. 교재 목록에서 상태 확인
   - ⏳ 파싱 중: PROCESSING
   - ✅ 완료: DONE
   - ❌ 실패: FAILED
3. "재파싱" 버튼 클릭 시 자동으로 상태 폴링

### 방법 4: API로 직접 확인

```bash
# 파싱 상태 조회
curl http://localhost:8000/api/v1/books/{book_id}/parse-status

# 응답 예시
{
  "book_id": "book_korean_2026_수능특강_문학_d139df",
  "status": "PROCESSING",
  "progress": 45
}
```

### 방법 5: 백엔드 콘솔 로그 확인

백엔드 서버를 실행한 터미널에서 로그 확인:

```bash
# 백엔드 서버 실행 중인 터미널에서
# 다음과 같은 로그가 출력됨:

[books] ========================================
[books] PDF 파이프라인 시작
[books] ========================================
[books] PDF 경로: ...
[books] 교재 ID: ...
[books] 진행률 업데이트: 10% (파이프라인 초기화)
[books] 진행률 업데이트: 20% (텍스트 추출 시작)
[books] 진행률 업데이트: 45% (페이지 45-50 처리 중)
...
[books] PDF 파이프라인 완료: book_id
```

## 파싱 상태 필드

### Book 테이블 필드

- `parse_status`: 파싱 상태
  - `PROCESSING`: 파싱 중
  - `DONE`: 완료
  - `FAILED`: 실패
  - `PENDING`: 대기 중

- `parse_progress`: 진행률 (0-100)
- `current_page`: 현재 처리 중인 페이지
- `total_pages`: 전체 페이지 수

## 파싱 단계별 진행률

1. **5%**: 파이프라인 시작
2. **10%**: 파이프라인 초기화
3. **20%**: 텍스트 추출 시작
4. **20-70%**: 페이지별 처리 (청크 처리 시)
5. **70%**: 파이프라인 완료
6. **70-100%**: 커리큘럼 생성 및 DB 동기화
7. **100%**: 완료

## 문제 해결

### 파싱이 멈춘 것 같을 때

1. **상태 확인**
   ```bash
   python scripts/check_parsing_status.py {book_id}
   ```

2. **진행률 확인**
   - `parse_progress`가 증가하는지 확인
   - `current_page`가 변경되는지 확인

3. **재시작**
   - 관리자 페이지에서 "재파싱" 버튼 클릭
   - 또는 교재 삭제 후 새로 업로드

### 로그가 보이지 않을 때

1. **백엔드 서버 터미널 확인**
   - 서버를 실행한 터미널에서 로그 확인
   - `print()` 문은 즉시 출력됨

2. **모니터링 스크립트 사용**
   ```bash
   python scripts/monitor_parsing.py {book_id}
   ```

3. **DB 상태 확인**
   ```bash
   python scripts/check_parsing_status.py {book_id}
   ```

### 방법 6: 파싱 진단 스크립트 (추천!)

파싱이 잘 되고 있는지, 실패 원인은 무엇인지 자동으로 분석합니다.

```bash
cd backend
python scripts/diagnose_parsing.py
```

**출력 예시:**
```
================================================================================
파싱 진단 리포트
================================================================================
진단 시간: 2026-01-24 00:00:47

--------------------------------------------------------------------------------
교재: 2026 수능특강_ 문학
ID: book_korean_2026_수능특강_문학_296749
상태: PROCESSING
진행률: 62%
페이지: 391/456

[진단] 파싱이 진행 중입니다.
  - 진행률: 62%
  - 남은 페이지: 65개

[WARNING] 파싱이 549.6분 동안 진행 중입니다.
     → 파싱이 멈춘 것일 수 있습니다.
     → 재파싱을 시도하세요.
```

**실패한 경우:**
```
[진단] 파싱이 실패했습니다.

[원인 분석]
  ❌ 강의가 0개입니다.
     가능한 원인:
     1. PDF에서 강의 제목을 찾지 못함
     2. 강의 제목 패턴이 맞지 않음
     3. OCR 품질이 낮아 텍스트 추출 실패

     해결 방법:
     1. 캐시 삭제 후 재파싱
     2. config.json의 강의 제목 패턴 확인
     3. Tesseract 한국어 언어팩 설치 확인
```
